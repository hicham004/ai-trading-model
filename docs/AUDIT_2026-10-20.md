# Audit — AI Trading Model — 2026-10-20

Author: Claude (Fable 5.1). Scope: code, docs, GitHub state, live tests run
locally (public data only), and external research. Nothing in the repo was
changed by the audit. The plan that follows from it is
`docs/MASTER_PLAN_2026-10-20.md`.

## Verdict

The safety and operations plumbing is genuinely good. The thing the owner wants
(a 24/7 pro-grade trader with an AI reading the news) is not built: one toy
strategy with no proven edge, a software-only stop checked once an hour, and an
AI/news layer that exists only as a design document. The repo has been idle
since June 29, 2026. One time-critical defect: **every WebSocket default uses
port 8443, which OKX discontinues on Oct 31, 2026.**

| Goal | What exists | Status |
|---|---|---|

| Trades like a professional | `ma_crossover` SMA(10/30) on 1H BTC-USDT, long-only, 10 USDT/entry, ≤3/day | Toy strategy, no edge shown |
| Protects positions like a pro | Software stop evaluated only on confirmed 1H closes (`app/execution/driver.py:517-523`) | Up to 60 min late; exits at market |

| Validated before trusting | Static invariants only; no walk-forward/holdout; no Sharpe/Sortino | Not built |

Proportions: ~21K lines code, ~9.5K tests, ~5.2K governance docs, 244 lines of strategy.

## 3. Urgent: OKX port-8443 cutoff (Oct 31, 2026)

OKX changelog: WebSocket connections on port 8443 stop on Oct 31, 2026 (public internet; Colo Nov 16) for every path including `/ws/v5/public`, `/ws/v5/private`, `/ws/v5/business`, explicitly including demo `wspap.okx.com`. REST unaffected. Fix: remove `:8443`.

Affected defaults: `app/config.py:135-140`, `app/config.py:265`, `app/exchange/okx_public_ws.py:57-58`, `app/exchange/okx_demo_endpoints.py:48-50`, `.env.example:31-32,94`, `docs/PHASE3A_LIVE_DATA.md`, `docs/PHASE5_DEMO_TRADING.md`. Validators (`_APPROVED_WS_PORTS = (None, 443, 8443)`) already accept port-less URLs. Without the fix the VPS feed dies on Oct 31 and the supervisor fails closed (silent stall; only a stale-heartbeat alert).

Also from the changelog: Sept 30 USD→USDC spot migration does not affect USDT pairs; SBE binary order entry (demo early Nov) is optional.

## 4. Strategic assessment

Right (and research-backed): the LLM never touches orders; deterministic risk veto; fail-closed; demo-only header unrepresentable; idempotent orders; reconciliation; account-partition guard; limit orders by default. Phase 6b's defensive-only vocabulary matches the evidence (LLM traders lose: Alpha Arena S1 4/6 lost; LLM news sentiment weak out-of-sample; news agent in a multi-agent portfolio reduced volatility, not returns).

Wrong or weak:
1. Edge was never the priority; the demo venue runs a strategy never walk-forward tested. The shadow run measures plumbing, not profitability.
2. "Confidence" = `0.55 + 10 × SMA gap` (`app/strategy/library.py:64`), not a calibrated probability; the 0.60 floor forced the 1m→1H move and on 1H clears 87.5% of signals (barely filters).
3. Hourly software stop; exchange-side stop deferred since June. OKX docs show spot stop-loss via `/api/v5/trade/order-algo` with `tdMode: cash`; `attachAlgoOrds` on spot needs demo verification.
4. Sample-size trap: one strategy × one asset × a few trades/week ≈ 100 trades/year; cannot validate anything. Paper-trade many variants in parallel; use demo only for execution validation.
5. Process overhead ate velocity: travel-mode guards, notification workflows, smoke-test PRs, 20+ docs, a committed `resume_claude_at_1.sh`; no bulk history loader, `create_all` without migrations, no lockfile, CI 3.12 vs local 3.13.

## 5. Technology verdicts

Keep: Python/FastAPI/SQLAlchemy/PostgreSQL, the hand-written OKX WS client, Streamlit (observability only), systemd + heartbeat + Telegram. Add: vectorbt (research sweeps), DuckDB/Parquet, Alembic, uv/pip-tools lockfile, pip-audit. Reconsider later: nautilus_trader for perps/multi-venue. Obsolete: OpenClaw plan. No rewrite — the safety core is the asset.
