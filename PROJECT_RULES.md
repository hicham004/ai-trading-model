# Project Rules

## Purpose

This repository is for building an AI-assisted automated OKX trading system.
The final goal is a bot that can eventually place trades automatically through
a controlled execution layer. It is not a dashboard-only project and it is not
a manual signal service.

That final capability is not currently authorized. The project must progress
through historical research, realistic backtesting, live public data, local
paper trading, OKX demo trading, and long out-of-sample evaluation before tiny
live automation can be considered.

## Intended Architecture

```text
historical public OKX REST data
-> local database
-> realistic backtesting and strategy research
-> live public OKX WebSocket data
-> local paper broker and forward-testing loop
-> OKX demo trading
-> AI news/event research layer
-> risk manager final veto
-> tiny controlled live OKX executor, much later
```

Dashboard, API, logging, and alerts are observability tools around this system.
They are not the final product or the source of trade authority.

## Decision And Execution Authority

- AI/LLM components may research news and markets, classify events, explain
  signals, identify regimes, and adjust bounded confidence.
- AI/LLM components must never call order endpoints or directly authorize,
  place, modify, or cancel orders.
- Strategies produce structured signals; they do not execute.
- Every future actionable signal must pass deterministic validation and the
  risk manager.
- The risk manager has final veto.
- Only a controlled execution module may submit an order, and only in a phase
  explicitly approved for that environment.

## Security

- Keep secrets out of Git, source code, logs, tests, screenshots, prompts, and
  documentation.
- `.env.example` is documentation only and must contain no real credentials.
- Do not request or use production OKX private API keys in the current
  approved scope. Demo keys are allowed only for the explicitly authorized
  demo/simulated Phase 5 and Phase 6a paths, only through environment
  variables, and never in Git, logs, screenshots, prompts, or docs.
- New authenticated exchange access beyond the reviewed demo/simulated scope
  requires a separate approved phase and human security review.
- Withdrawal functionality and withdrawal permissions are permanently
  prohibited.
- Future demo/live keys must use least privilege; live keys must never include
  withdrawal permission.

## Trading Risk

- No real-money orders, production OKX execution, or live-funds execution in
  the current approved scope.
- No martingale, doubling down, averaging down after losses, or automated loss
  chasing.
- No strategy may be considered based on one favorable backtest.
- Clearly label every simulated result as a simulation.
- Backtest, paper, and demo results never independently authorize live trading.
- A no-trade decision is valid and must override opportunity seeking.

Before approval, backtesting must account for:

- fees;
- slippage;
- funding where applicable;
- bid/ask spread;
- gaps through stop-loss prices;
- stale data and stale signals;
- wrong instrument, timeframe, and timestamp alignment;
- data quality and duplicate/missing bars;
- look-ahead and survivorship bias where applicable; and
- later out-of-sample and walk-forward validation.

## Phase Approval

A phase is complete only when:

1. Its approved implementation exists.
2. Normal tests pass.
3. Adverse-case and safety tests pass.
4. Independent reviewer findings are resolved.
5. Documentation accurately matches implementation and limitations.
6. Security and risk controls for that phase are reviewed.
7. The human owner explicitly approves the phase.

No single agent can build, review, and approve the same phase. Passing tests,
writing a completion report, or updating a roadmap does not constitute
approval.

## Engineering

- Keep collection, features, strategies, risk, execution, AI research, and
  observability separated.
- Prefer deterministic, auditable order authorization over opaque agent action.
- Use reproducible configuration, structured logs, and pinned important
  dependencies.
- Add tests proportional to risk, including failure and adversarial cases.
- Prefer official documentation and maintained dependencies.

## Change Control

- Ask before changing the agreed scope.
- Do not begin a later phase because an earlier prototype exists.
- Authenticated OKX demo access (Phase 5) was explicitly authorized, reviewed,
  and explicitly accepted by the human owner on June 10, 2026 for the
  demo/simulated environment only. Phase 6a mechanical shadow operation is
  separately authorized for the reviewed demo path only. Real/live trading
  still requires separate explicit human approval. Phase 4 paper trading is
  local simulation only.
- Tiny live trading, if ever approved, requires strict capital limits,
  position limits, leverage limits, daily/weekly loss limits, stop-losses,
  reconciliation, idempotency, monitoring, a kill switch, and an emergency
  human stop.
